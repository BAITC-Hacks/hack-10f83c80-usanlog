# Подбор подрядчиков для мероприятий

Минимальный веб-сервис для каталога event-подрядчиков Казахстана. Принимает город, дату, тип мероприятия, категорию и бюджет; дополнительно — длительность и язык. Возвращает до трёх свободных вариантов с объяснениями по данным карточек.

## Запуск

Требуется Python 3.9 или новее. Внешние библиотеки не нужны.

```sh
python3 server.py
```

Откройте <http://localhost:8000>.

Каталог находится в `data/providers.csv`. Чтобы подключить OpenAI или совместимый API, задайте переменные окружения из `.env.example`, затем перезапустите сервер. Ключ хранится только в окружении процесса. Без ключа сервис работает локально: жёсткие фильтры и стабильные объяснения по проверяемым полям остаются доступны.

Для другого API используйте `OPENAI_BASE_URL` с корнем `/v1`; выбранная модель должна поддерживать Chat Completions, JSON mode и endpoint embeddings.

## Как подбирает

1. Город и категория определяют исходный пул; далее подрядчики с синтетическими записями исключаются.
2. Исключаются занятые на дату, неподходящие по формату, цене, языку и (если задано) длительности. Неуказанные в каталоге значения не считаются подтверждённым совпадением.
3. Если API настроен, эмбеддинги описаний сопоставляются с запросом и задают порядок только среди прошедших жёсткие фильтры. При совпадении оценок порядок стабилизируется ценой и ID. Без API порядок также устойчив: цена, затем ID.
4. LLM формулирует объяснения только по фактам отобранных карточек. При ошибке API используются шаблонные объяснения по правилам.

`price_imputed` и `city_imputed` не скрываются: такие значения отмечаются как ориентировочные. Площадки обрабатываются как обычные категории подрядчиков. Бронирования и обращения к подрядчикам отсутствуют.

API:

- `GET /api/options` — варианты для формы;
- `POST /api/recommend` — подобрать варианты. Обязательные поля: `city`, `event_date` (`YYYY-MM-DD`), `event_type`, `category`, `budget_kzt`; дополнительные: `duration_hours`, `language`.

Статусы ответа: `recommendations`, `no_catalog`, `no_match`.
